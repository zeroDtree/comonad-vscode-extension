# 上下文

一次请求携带的不只是对话：还有系统提示与本轮可用工具的定义。它们都从模型的窗口里扣，所以 128K
模型并不等于 128K 聊天。

## 窗口

窗口是提供商上的数据（`contextWindow`）。模型菜单里的 **Auto** 解析为当前模型自己的窗口；固定
档位用于端点文档与实际不符的情况。没有配置窗口的模型回退到 128K，并在 `/context` 中说明。

用 `/context` 查看：

- 窗口大小与回复预留；
- 系统提示与工具定义开销；
- **权威转录**（完整聊天，始终保留）；
- **模型上下文**（摘要 + 最近 tail）；
- 摘要覆盖范围与 version；
- 自动压缩的触发点、保留目标与当前估算压力；
- 上一次请求的实际 prompt 大小与占比。

输入框上方的状态行显示同样的占比，例如
`15.7M tokens · $0.000 · cache 8M (51%) · turn 5 · context 80% · 204K/256K`。数字会按 K/M/G
自动缩放；`cache` 是累计命中 provider prompt cache 的输入量及其占全部输入的比例；provider
不报告缓存统计时整段省略，而不是显示为 `0 (0%)`。

provider 尚未测量该聊天时，context 一段是本地估算，带 `~` 标记，例如
`turn 0 · context ~27% · ~69K/256K`；首个完成的往返会替换为 provider 的精确计数。provider
始终不上报 usage 时，该估算会一直保留。

## 压缩

压缩是**模型上下文操作**，不是聊天编辑。`Session.transcript` 是权威记录，摘要永远不会缩短它；
模型收到的是派生摘要 + 覆盖范围之后的 turns。最新回合始终逐字保留；之后的摘要会扩展现有摘要，
而不是从头开始。

聊天把摘要显示成卡片。被摘要覆盖的 turns 仍保存在权威记录里，默认折叠在 **Show original messages**
下；**Load older messages** 可以继续向前分页查看完整历史。**Rebuild**（或 `/summarize --rebuild`）
会从完整权威记录重写摘要。

自动压缩是主动的。**每次模型请求之前**（不只是用户回合开始时），agent 都会估算整个请求（系统提示、
工具定义与消息），用 provider 上次报告的同一请求 prompt 大小校准估算，再与窗口比较。剩余空间不足
`compactionHeadroom` 个 token 时（默认 20,000；`0` 关闭主动压缩），它会把当前回合之前的 turns 折叠
进摘要，只保留一小段原文 tail：窗口的 `compactionRetainPercent`（默认 10%）。当前回合永远不会被折叠，
回复预留也仍然保留。两个设置都在 设置 → Agent 中。

处理顺序是：到阈值先摘要；请求仍放不进“窗口 − 回复预留”时才省略旧工具输出；最后才是端点拒绝后的
一次强压缩重试。subagent 请求无法按聊天记录折叠，只能省略。摘要成功会通知一次前后大小；裁剪通知
每回合最多一次。摘要是一次短的非思考调用，每回合最多尝试四次；失败只通知一次，
回合继续。

结果：

- 预算计入请求携带的一切，包括 DeepSeek 要求回传的 assistant reasoning。这正是本地估算可能低于窗口、
  而 provider 报告的 prompt 更大的原因；校准让触发点保持诚实。
- 用户 prompt 在轮首压缩之前就写入权威转录，所以重载、Stop 或失败回合都不会丢失它。
- **压缩不移动恢复点。** 恢复点指向权威消息索引，任意次摘要后文件恢复仍然有效。
- 旧附件仍被权威记录引用；压缩不会把它们扫掉。

端点以“too long”拒绝的请求会在强压缩后重试一次，所以窗口估错只损失一次重试，而不是整个回合。

用 `/summarize [notes]`（别名 `/compress`、`/compact`）按需扩展摘要；`--rebuild` 从完整聊天重写。

## 模型看到什么

**Context** 设置（设置 → Agent → Context）作用于最近 tail；摘要始终包含，不会被过滤掉：

| 形态 | 发送内容 |
| --- | --- |
| Rendered | 摘要 + 文本、思考与工具结果，长工具输出会被裁剪 |
| Token | 摘要 + 仅用户与 assistant 文本 |
| Raw | 摘要 + 完整的最近记录 |

**Display** 设置（设置 → UI → Display）只改变你看到的内容；Context 改变模型收到的内容。

## 引用与附件

`@` 引用解析为**用户消息**上的类型化附件，而不是 system prompt：带编号的文本、图片，或带页码的 PDF
文本。单条上限 20k 字符、合计 60k，并受读取隔离和 deny 规则过滤。解析结果是随该轮保存的快照，后续
回合与重放都不会重新读取文件。

图片和 PDF 存在内容寻址存储里，转录只保留元数据；见[聊天](/zh/guide/chat#图片与-pdf)。
