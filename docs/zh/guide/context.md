# 上下文

一次请求携带的不只是对话：还有系统提示、本轮可用工具的定义，以及内容层组装的一切。它们都从模型的
窗口里扣，所以 128K 模型并不等于 128K 聊天。

## 窗口

窗口是模型 profile 上的数据（`contextWindow`）。模型菜单里的 **Auto** 解析为当前模型自己的窗口；固定
档位用于端点文档与实际不符的情况。没有配置窗口的模型回退到 128K，并在 `/context` 中说明。

用 `/context` 查看：

- 窗口大小与回复预留；
- 系统提示与工具定义开销；
- 转录与指令开销；
- 上一次请求的实际 prompt 大小与占比。

输入框上方的状态行显示同样的占比，例如 `context 43% · 55K/128K`。

## 压缩

超过窗口后，旧回合会被**摘要，而不是截断**。最新请求逐字保留；摘要写回聊天，你能看到它；之后的摘要
会扩展现有摘要，而不是从头开始。

三个结果：

- 一个回合在运行中超出窗口时，按代价从低到高分两步处理：先省略旧工具输出，仍放不下才折叠更早的回合。
  当前回合永远不会被折叠。
- 摘要失败不会改变任何东西。对话保持原样，回合继续从它作答。
- **恢复点跟随摘要。** 压缩会替换回合，落在被替换回合里的恢复点无法再兑现而被丢弃；其余恢复点仍指向
  同一条消息。压缩后最早的恢复点是摘要本身。

端点以“too long”拒绝的请求会在强压缩后重试一次，所以窗口估错只损失一次重试，而不是整个回合。

用 `/summarize`（别名 `/compress`、`/compact`）按需折叠对话。压缩保留最新回合，并把摘要写回聊天。

## 模型看到什么

**Context** 药丸决定聊天回传什么：

| 形态 | 发送内容 |
| --- | --- |
| Rendered | 文本、思考与工具结果，长工具输出会被裁剪 |
| Token | 仅用户与 assistant 文本 |
| Raw | 完整记录 |

**Display** 只改变你看到的内容；Context 改变模型收到的内容。

## 引用与图片

`@` 引用在回合运行时解析为带编号的块，单条上限 20k 字符、合计 60k，并受读取隔离和 deny 规则过滤。
图片存在转录之外，以图像内容发送；见[聊天](/zh/guide/chat#图片)。
