# 上下文

一次请求携带的不只是对话：还有系统提示、本轮可用工具的定义，以及内容层组装的一切。它们都从模型的
窗口里扣，所以 128K 模型并不等于 128K 聊天。

## 窗口

窗口是模型 profile 上的数据（`contextWindow`）。模型菜单里的 **Auto** 解析为当前模型自己的窗口；固定
档位用于端点文档与实际不符的情况。没有配置窗口的模型回退到 128K，并在 `/context` 中说明。

用 `/context` 查看：

- 窗口大小与回复预留；
- 系统提示与工具定义开销；
- **权威转录**（完整聊天，始终保留）；
- **模型上下文**（摘要 + 最近 tail）；
- 摘要覆盖范围与 version；
- 上一次请求的实际 prompt 大小与占比。

输入框上方的状态行显示同样的占比，例如 `context 43% · 55K/128K`。

## 压缩

压缩是**模型上下文操作**，不是聊天编辑。`Session.transcript` 是权威记录，摘要永远不会缩短它；
模型收到的是派生摘要 + 覆盖范围之后的 turns。最新回合始终逐字保留；之后的摘要会扩展现有摘要，
而不是从头开始。

聊天把摘要显示成卡片。被摘要覆盖的 turns 仍保存在权威记录里，默认折叠在 **Show original messages**
下；**Load older messages** 可以继续向前分页查看完整历史。**Rebuild**（或 `/summarize --rebuild`）
会从完整权威记录重写摘要。

结果：

- 一个回合在运行中超出窗口时，按代价从低到高分两步处理：先省略旧工具输出，仍放不下才扩展摘要。
  当前回合永远不会被摘要。
- 摘要失败不会改变任何东西。模型上下文保持原样，回合继续从它作答。
- **压缩不再移动恢复点。** 恢复点指向权威消息索引，任意次摘要后文件恢复仍然有效。
- 旧附件仍被权威记录引用；压缩不会把它们扫掉。

端点以“too long”拒绝的请求会在强压缩后重试一次，所以窗口估错只损失一次重试，而不是整个回合。

用 `/summarize [notes]`（别名 `/compress`、`/compact`）按需扩展摘要；`--rebuild` 从完整聊天重写。

## 模型看到什么

**Context** 药丸作用于最近 tail；摘要始终包含，不会被过滤掉：

| 形态 | 发送内容 |
| --- | --- |
| Rendered | 摘要 + 文本、思考与工具结果，长工具输出会被裁剪 |
| Token | 摘要 + 仅用户与 assistant 文本 |
| Raw | 摘要 + 完整的最近记录 |

**Display** 只改变你看到的内容；Context 改变模型收到的内容。

## 引用与附件

`@` 引用解析为**用户消息**上的类型化附件，而不是 system prompt：带编号的文本、图片，或带页码的 PDF
文本。单条上限 20k 字符、合计 60k，并受读取隔离和 deny 规则过滤。解析结果是随该轮保存的快照，后续
回合与重放都不会重新读取文件。

图片和 PDF 存在内容寻址存储里，转录只保留元数据；见[聊天](/zh/guide/chat#图片与-pdf)。
